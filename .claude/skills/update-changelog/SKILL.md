# 更新 CHANGELOG.md

在合并分支之前,由用户手动调用。目标:让根目录的 `CHANGELOG.md` 如实记录这个分支带来的改动。

## 格式

- 文件在项目根目录,第一行是 `# 更新日志`
- 每个日期一个二级标题:`## YYYY-MM-DD`,**最新的日期在最上面**
- 日期下面是项目符号列表,一条一行
- 同一天的所有改动放在同一个日期标题下,不重复建标题
- 不写提交哈希、不写作者

示例:

```markdown
# 更新日志

## 2026-11-20

- 首页样式改为响应式、手机优先,新增响应式测试
- 新增 `validate` 脚本(类型检查加测试)

## 2026-11-18

- 初始化 TypeScript 项目骨架
- 验证 `node:sqlite` 能在 Vitest 里使用
```

## 怎么写每一条

- 写"改了什么、对使用者或项目有什么意义",不要照抄提交标题
- 一条一件事;同一个功能的多个小提交合并成一条
- 用中文,和 specs 里的文档保持一致;命令、文件名、代码标识符用反引号
- 只记有实际意义的改动(功能、修复、配置、测试、文档规则变化)。
  纯格式调整、只改 CHANGELOG.md 本身的提交不记
- 不夸大:没做完或没验证的东西不写成已完成

## 步骤

1. **只读检查**:运行 `git status --short`、`git branch --show-current`,
   并确认 `CHANGELOG.md` 是否存在。
2. **没有 `CHANGELOG.md`(首次)**:
   1. 运行 `git log --reverse --format='%ad|%h|%s' --date=short`,取得全部提交
   2. 按日期分组;需要时用 `git show --stat <哈希>` 看清楚提交实际改了什么
   3. 为每个日期写若干条,最新日期在最上面,新建文件
3. **已有 `CHANGELOG.md`**:
   1. 完整读一遍现有内容,记下已有的日期标题和条目,避免重复
   2. 找出本分支新增的提交:`git log <主分支>..HEAD --format='%ad|%h|%s' --date=short`
      (主分支通常是 `main`;不确定就问用户)
   3. 再看尚未提交的改动:`git status --short` 和 `git diff`(含未跟踪文件)
   4. 已提交的改动用提交日期;未提交的改动用今天的日期
   5. 如果某个日期标题已存在,把新条目加到该标题下;否则在文件最上方新增标题
   6. 已经记过的内容不要重复添加
4. **自检**:日期标题从新到旧、没有重复的日期标题、每条都是一行、没有遗漏本分支的主要改动。

## 规则

- 只修改 `CHANGELOG.md`,不改其他文件
- **不要提交**(不运行 `git add`、`git commit`)。写完后告诉用户新增了哪些日期和条目,
  由用户检查后和其他改动一起提交
- 不确定某个改动该不该记、或者该归到哪一天,问用户,不要猜
- 不删除、不改写已有的旧条目,除非用户明确要求
